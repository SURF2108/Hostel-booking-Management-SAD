# Engineering blueprint
Use a modular monolith unless diagrams require otherwise. JavaScript ES modules, React + Vite, React Router, Express, Mongoose, MongoDB, npm, CSS design tokens, Lucide icons. Select compatible maintained Node LTS and package versions; pin via lockfile and engines. Prefer native fetch with a central API client; avoid unnecessary libraries. Use npm workspaces if practical; root commands must work on Windows PowerShell. No global dependencies required beyond documented prerequisites.
Suggested layout (adapt to existing repository): client/src/{components,layouts,pages,features,lib,styles}; server/src/{config,models,routes,controllers,services,middleware,validators}; server/tests; docs; diagrams (unchanged). API prefix /api/v1. Keep app construction separate from listener so tests can import app. Controllers handle HTTP, services enforce business invariants, models define persistence. Do not expose Mongoose documents containing secrets. Validate request bodies, params and queries on server. Standard JSON errors with stable code, message and field errors; correct 400/401/403/404/409/500 status codes. Pagination, filtering and stable sorting for lists; whitelist update fields. Avoid exposing stack traces.
Authentication: bcrypt password hash, rate-limit login, HTTP-only SameSite cookies for session/JWT, Secure in production; protect mutations against CSRF with origin checks and appropriate token strategy; explicit CORS allowlist if separate origins. Prefer same-origin Vite proxy locally. Enforce role and record ownership on every protected endpoint; never rely on React guards alone. No hardcoded secrets or public admin signup. Generate local secret with Node crypto; write ignored .env, include safe .env.example. No real credentials in logs or seed.
Model design derived from diagrams. Typical entities may include User, Hostel, Room, Bed, Booking; include only relevant entities. Store references, unique identities, timestamps, indexes, and explicit state enums. Money as integer minor units; dates with clear timezone and interval semantics. Compute price, availability and permissions on server. Prevent double-booking under concurrent requests using database-enforced uniqueness for allocation keys or transactionally guarded slot/room writes for overlapping periods. A naive check-then-insert is not acceptable. For multi-document transactions use a replica set; document local setup. Idempotent booking confirmation/cancellation, valid transitions only, release capacity consistently, preserve booking history. Validate capacity, invalid date ranges, stale requests and deleted/inactive inventory. Test parallel requests against real MongoDB. Never use in-memory data as production fallback.
Support existing local MongoDB URI or MongoDB Atlas URI supplied by user. Provide optional compose.yaml local replica set if needed; no assumption Docker installed. Verify database connection before marking app ready. If no local DB available, complete code and document blocker; do not fake persistence. Tests isolated to dedicated test database and guard against production URI. Seed idempotently without deleting user data. Root scripts: dev, build, lint, test, test:e2e, seed, start (or document exact equivalents). Add health/readiness checks, graceful shutdown, README run instructions, env validation, and deterministic demo fixtures.
