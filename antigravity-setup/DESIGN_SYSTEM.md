# Neo-brutalism + Bauhaus
Create a distinctive architectural editorial interface, not a generic admin template. Warm paper canvas, stark black ink, geometric composition, functional primary colors, asymmetric grids, tactile hard shadows. Avoid gradients, glassmorphism, blurred shadows, decorative emoji, icon fonts with emoji, excessive rounding, stock imagery and gratuitous animations. Icons: consistent Lucide SVG stroke 2; text labels for ambiguous actions. Decorative circle, square, triangle, stripe and grid shapes using CSS/SVG, never obscure content.
## Tokens
Canvas #F5F1E8; surface #FFFDF7; ink #171717; muted #595959; red #E94235; blue #2454D8; yellow #F4C542; success #226344. Use white or dark text based on measured contrast; use dark ink on yellow; do not assume white passes on red. Border 2px solid ink; featured panels 3px; shadow 5px 5px 0 ink; pressed shadow 2px 2px with small transform; radius 0–4px. Spacing 4/8/12/16/24/32/48/64. Typography: Space Grotesk or local/system geometric sans heading, Inter/system sans body; robust fallback without network. Heading 40–64 desktop, 28–36 mobile, body 15–16, labels 12–14. Use weight 600–800 headings, 400–500 body. No tiny unreadable type.
## Composition
Desktop: compact left navigation for authenticated dashboards, main content with consistent max width and top bar; public views editorial header and geometric hero only if public flow exists. 12-column desktop, 6 tablet, 4 mobile. Responsive room/inventory cards with strong borders, capacity/availability badges with text, clear primary action, useful filters. Use a deliberate color hierarchy: blue for primary navigation/actions, yellow for key callouts, red for destructive actions or decorative emphasis; maintain contrast. Dashboard statistics use real API data and avoid unnecessary charts. Tables have clear headers, mobile scrolling or stacked rows, accessible sorting if implemented. Booking form has visible summary, confirmation, validation, clear status timeline if supported. Administrative actions have confirmations for destructive operations. Every page must be visually coherent with shared components, not duplicated CSS.
## Components and interaction
Build reusable Button, Input, Select, Card, Badge, Alert, Dialog, Table, Skeleton, EmptyState, ErrorState, navigation and layout. Focus outlines, keyboard interaction, semantic labels, dialog focus return, ARIA live errors and reduced motion. Touch targets at least 44px where feasible. Loading, empty, error, permission denied and success states everywhere applicable. Disable submit while pending, preserve input after recoverable errors. No silent failure, no fake counters, no nonfunctional controls. Test 360, 768 and 1440px widths and keyboard navigation. Capture actual screenshots of key screens after implementation, not design mockups.
